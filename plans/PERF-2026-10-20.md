# React performance pass, 2026-10-20

Rules: Vercel React Best Practices (`claudeskills/.claude/skills/vercel-react-best-practices`). The server and RSC
rules don't apply to a Vite SPA. The async rules were applied to the `/api` functions and to client fetches.
Priority device is a mid-range phone, so bundle size and main-thread time weigh most.

Line numbers are as of `f0658d6`, the commit before this pass. Every finding was checked against the code and, where
it could be, measured. Where something is already fine, the table says so.

## How it was measured

- **Bundle.** `vite` can't be installed in this sandbox (no npm registry), so builds used esbuild with the same
  settings a production Vite build uses: ESM, code splitting, minified, `NODE_ENV=production`. Sizes are minified
  bytes, with gzip -9 in brackets.
- **Main thread.** Playwright Chromium, a 390x844 viewport, 4x CPU throttling over CDP, demo mode
  (`sources.session = {"mode":"demo"}`), opened on `#wire`. Medians of 7 runs (5 at 1280).
- **Engine.** A Node benchmark of the startup engine calls on the demo league, plus byte-for-byte output comparison
  against the previous engine.
